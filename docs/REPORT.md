# Отчёт о работе с ИИ — Balance & Progression Studio

> Черновик. Разделы, помеченные **[заполнить]**, описывают ваш собственный опыт: какие промпты вы писали, что проверяли, где ИИ ошибся. Их нужно заполнить самостоятельно, иначе отчёт превратится в «ИИ сгенерировал всё», за что снижают баллы.

## 1. Модули

1. **Импорт.** CSV/JSON, drag&drop, автоопределение разделителя и кодировки. Валидация: обязательные колонки, числа, диапазоны, дубли ID. Предпросмотр с подсветкой ошибок, импорт только корректных строк или всех.
2. **Таблица.** Редактирование в ячейках, добавление и удаление строк, сортировка, поиск, проверка на лету, автосохранение в localStorage. Аудит баланса.
3. **TTK.** `max(A − D, A × k) × M` с критами через ожидаемое значение. Пошаговый расчёт, разброс, проверка симуляцией Монте-Карло, матрица TTK.
4. **Прогрессия.** Степенная и экспоненциальная формулы, таблица уровней, время прокачки, рост статов, график на Chart.js.
5. **Лут.** Проверка суммы = 100% по каждой таблице, подсветка, нормализация, ожидаемый дроп, отчёт CSV/JSON.

## 2. Ручная проверка формул

Повторите каждый расчёт на калькуляторе или на бумаге, затем сравните с приложением и приложите скриншот.

### Пример 1. Урон и TTK без критов
Лучник (A = 35) → Мечник (HP = 120, D = 10), k = 0.1, M = 1, крит 0, 1 атака/с.
- Урон = max(35 − 10, 35 × 0.1) × 1 = max(25, 3.5) = **25**
- Ударов = ceil(120 / 25) = ceil(4.8) = **5**
- TTK = 5 / 1 = **5 с**
- В приложении: **[заполнить: совпало / скриншот]**

### Пример 2. Нижняя граница урона и криты
Мечник (A = 25) → Рыцарь (HP = 180, D = 20), k = 0.1, крит 20%, ×2.
- База = max(25 − 20, 2.5) = **5**
- Ожидаемый = 5 × (1 + 0.2 × (2 − 1)) = **6**
- Ударов = ceil(180 / 6) = **30**, все удары критуют → ceil(180 / 10) = 18, без критов → 36
- В приложении: **[заполнить]**

### Пример 3. Кривая опыта
Степенная, a = 100, b = 1.5, c = 0.
- xp(1) = 100 × 1^1.5 = **100**
- xp(2) = 100 × 2^1.5 = 282.84 → **283**
- xp(3) = 100 × 3^1.5 = 519.62 → **520**
- Всего до 4-го уровня = 100 + 283 + 520 = **903**
- В приложении: **[заполнить]**

### Пример 4. Лут
Таблица `chest`: Меч 30%, Щит 30%. Сумма 60% — это ошибка. После «Привести к 100%»: 30 / 60 × 100 = **50%** каждому.

Эти же примеры записаны как автотесты в `tests/` (`npm test`).

## 4. Где ИИ ошибся (2–3 случая)

**[заполнить]** Для каждого случая: что было не так, как вы это заметили (ручной расчёт, тест, странное поведение в браузере) и как исправили.

Подсказки, где ИИ часто ошибается в таких задачах (проверьте у себя):
- `ceil(HP / урон)` при точном делении из-за погрешности float может дать лишний удар (180 / 6.000000001).
- Сумма 33.33 + 33.33 + 33.34 в JS не равна ровно 100. Без допуска проверка лута ложно падает.
- `ceil(HP / средний урон)` ≠ средний TTK по симуляции: оценка по среднему может отличаться на один удар.
- Перерисовка таблицы при каждом нажатии клавиши сбрасывает фокус ввода.
