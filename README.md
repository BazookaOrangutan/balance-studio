# Balance & Progression Studio

Статическое веб-приложение для геймдизайнера: загрузить таблицу статов, посчитать урон и время до убийства (TTK), настроить кривую опыта, проверить таблицы лута и выгрузить результат в CSV/JSON.

Без сервера и базы данных: всё работает в браузере, данные хранятся в `localStorage`.

**Демо:** https://bazookaorangutan.github.io/balance-studio/

## Модули

| # | Вкладка | Что умеет |
|---|---------|-----------|
| 1 | **Импорт** | CSV и JSON через выбор файла или drag&drop. Разделитель CSV определяется сам (`,` `;` Tab), кодировка UTF-8 или Windows-1251. Проверяет обязательные колонки, числа, диапазоны и дубли ID. Перед импортом показывает предпросмотр с подсвеченными ошибками. Экспорт всех данных и проекта целиком. |
| 2 | **Таблица** | Редактирование юнитов прямо в ячейках, добавление и удаление строк, сортировка, поиск, проверка на лету, автосохранение. Аудит баланса: юниты, которые доминируют или бесполезны за свою цену. |
| 3 | **TTK** | Урон с учётом атаки, защиты, множителя и критов. Пошаговый расчёт с подставленными числами, разброс из-за критов, проверка симуляцией (10 000 боёв), дуэль, матрица TTK «каждый против каждого». |
| 4 | **Прогрессия** | Степенная или экспоненциальная формула опыта с настраиваемыми коэффициентами, таблица уровней, время прокачки, рост статов юнита, график на Chart.js. |
| 5 | **Лут** | Сумма шансов в каждой таблице дропа должна быть 100%, ошибки подсвечиваются. Кнопка «Привести к 100%», ожидаемое количество за 100 открытий, отчёт в CSV/JSON. |

Дополнительно: тёмная тема (☾ в шапке), адаптивная вёрстка, горячие клавиши (`?` в приложении).

## Запуск локально

Нужен [Node.js](https://nodejs.org) 18+. Приложение использует ES-модули, а они не загружаются при открытии `index.html` двойным кликом (`file://`), поэтому нужен локальный сервер:

```bash
npm start
```

Откройте http://localhost:5173. Подойдёт и любой другой статический сервер, например расширение Live Server в VS Code или `python -m http.server`.

## Тесты

Формулы, парсер CSV и валидация покрыты тестами на встроенном `node:test`, ничего ставить не нужно:

```bash
npm test
```

В тестах ожидаемые значения посчитаны вручную, расчёт записан в комментарии рядом.

## Формат данных

### Юниты

| Колонка | Обязательная | Описание |
|---|---|---|
| `id` | да | уникальный идентификатор |
| `name` | да | название |
| `hp` | да | здоровье, ≥ 1 |
| `attack` | да | атака, ≥ 0 |
| `defense` | да | защита, ≥ 0 |
| `cost` | да | цена, ≥ 0 |
| `crit_chance` | нет | шанс крита 0…1 |
| `crit_mult` | нет | множитель крита ≥ 1 |
| `attack_speed` | нет | атак в секунду |

### Лут

| Колонка | Обязательная | Описание |
|---|---|---|
| `table` | да | имя таблицы дропа |
| `item` | да | предмет (строка «Ничего» тоже допустима) |
| `chance` | да | вероятность в %, сумма по таблице = 100 |
| `min_qty`, `max_qty` | нет | количество за выпадение |

Лишние колонки не теряются: они сохраняются и выгружаются как есть. JSON принимается в виде массива объектов или объекта с полем `rows`/`units`/`loot`.

### Тестовые файлы в `data/`

- `units.csv` — 12 юнитов с критами и скоростью атаки
- `units.json` — 10 юнитов в JSON
- `loot.csv` — 3 корректные таблицы лута
- `units_with_errors.csv` — разделитель `;` и специально внесённые ошибки: текст вместо числа, дубль ID, отрицательная защита, пустое имя, пропущенное поле, HP = 0
- `loot_with_errors.csv` — неверные суммы, дубль предмета, текст в `chance`, `min_qty > max_qty`

## Формулы

**Урон за удар**

```
base     = max(A − D, A × k) × M
expected = base × (1 + critChance × (critMult − 1))
удары    = ceil(HP / expected)
TTK      = удары / attackSpeed
```

`A` — атака, `D` — защита цели, `k` — минимальная доля урона (по умолчанию 0.1), `M` — общий множитель. Вычитание защиты легко понять: одна единица защиты блокирует одну единицу урона. Нижняя граница `A × k` не даёт урону упасть до нуля против танка.

Пример: Лучник (A = 35) бьёт Мечника (HP = 120, D = 10) без критов. Урон = max(25, 3.5) = 25, ударов = ceil(4.8) = 5, TTK = 5 с.

**Опыт до следующего уровня**

```
степенная:        xp(L) = round(a × L^b + c × L)
экспоненциальная: xp(L) = round(a × r^(L−1))
```

Пример: a = 100, b = 1.5 → 100, 283, 520, 800. Чтобы попасть на 4-й уровень, нужно 903 опыта.

**Аудит баланса**

Для каждой пары юнитов `edge(i, j) = TTK(j → i) / TTK(i → j)`. Сила юнита — среднее геометрическое `edge` против всех остальных. Затем сила делится на цену и сравнивается с медианой: на 25% выше медианы — «доминирует», на 25% ниже — «бесполезен». Порог настраивается.

## Структура проекта

```
index.html              разметка-оболочка: шапка, вкладки, справка
css/
  base.css              цветовые токены, светлая/тёмная тема, раскладка
  components.css        кнопки, карточки, формы, таблицы, бейджи
  tabs.css              стили отдельных вкладок
js/
  main.js               точка входа: вкладки, горячие клавиши, статус сохранения
  core/                 инфраструктура без бизнес-логики
    csv.js              парсер и сериализатор CSV
    schema.js           схемы наборов данных (колонки, диапазоны)
    validate.js         валидация и приведение типов
    store.js            состояние + автосохранение в localStorage
    io.js               чтение файлов, скачивание экспорта
    dom.js              хелперы для создания DOM
    samples.js          данные по умолчанию
  domain/               чистые формулы без DOM, покрыты тестами
    damage.js           урон, TTK, симуляция, дуэль
    progression.js      кривая опыта, рост статов
    loot.js             проверка сумм, нормализация, ожидаемый дроп
    audit.js            поиск доминирующих и бесполезных юнитов
    random.js           детерминированный ГПСЧ для симуляции
  ui/                   вкладки интерфейса
    dataGrid.js         редактируемая таблица (общая для юнитов и лута)
    importTab.js, tableTab.js, ttkTab.js, progressionTab.js, lootTab.js
    theme.js            переключатель темы
data/                   тестовые CSV/JSON
tests/                  тесты node:test
scripts/dev-server.js   локальный сервер без зависимостей
docs/REPORT.md          отчёт о работе с ИИ
```

Зависимости слоёв идут в одну сторону: `ui → domain → core`. Модули `domain/` не трогают DOM, поэтому их проверяет Node без браузера.
